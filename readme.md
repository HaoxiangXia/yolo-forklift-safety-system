# YSU2026大创项目-基于YOLO的叉车作业人车互斥报警系统设计与实现

本项目基于 **MaixCAM Pro** 与 **YOLO11** 模型，实现对实时画面中 **person（人）** 的稳定检测，并通过 **UART 串口** 向 ESP32 输出状态信号，用于驱动外部设备（LED、蜂鸣器）。

系统采用 **双 ROI（中心/外围）+ 双状态机** 的策略，实现“司机在位 + 危险区入侵”联合判断，从而显著降低误报，提高长期运行稳定性。

---

### 功能简介

- 使用 YOLO 对画面进行实时推理，仅关注 **person** 类目标
- 将画面划分为 **中心 ROI（驾驶员区）** 和 **外围 ROI（作业危险区）**
- ROI 判定标准：目标检测框中心点落入 ROI 内
- 使用 **双状态机** 抑制抖动：
    - center 状态机：驾驶员在位判定
    - outer 状态机：外围入侵判定
- 报警触发逻辑（互斥报警）：**center=ON 且 outer=ON → 报警输出 '1'** ，否则输出 '0'
- 仅在 **状态发生切换** 时通过 UART 发送数据，避免冗余通信
- 系统面向 **嵌入式边缘 AI** 长期运行场景

---

### 工作原理

1. 图像采集

    MaixCAM Pro 持续采集摄像头画面

2. 目标感知

    使用 YOLO11n 模型对画面进行推理，仅关注 person 类目标
3. ROI 分区判断（中心/外围）

    根据检测框中心点位置，将 person 判定为：
    - center_roi 内：驾驶员存在候选
    - outer_roi 内：外围入侵候选
4. 双状态机决策

    检测结果不会直接触发外设控制，而是进入状态机进行连续帧判断，以抑制抖动与误检

5. 最终报警输出

    仅当 **center_state = ON 且 outer_state = ON** 系统才进入报警状态，并通过 UART 输出 '1'。

    当报警解除时输出 '0'。

6. 外设控制

    ESP32 根据接收到的状态信号执行后续控制（LED、蜂鸣器）

检测结果不会被直接用于控制，而是先经过状态机决策，以保证输出信号的稳定性与可预测性。

---

### 串口通信设计说明

- UART 通信采用 **事件触发机制**

- 仅在系统状态切换时发送数据

- 避免逐帧或周期性发送，降低通信负载

- 输出信号语义清晰：

    - '1'：报警（司机在位 + 外围有人入侵）

    - '0'：非报警

该设计适合长期运行场景，有利于系统稳定性与外设可靠控制。

---


### 日志与调试设计

- 系统日志仅记录
    - 状态切换事件
    - 初始化失败
    - UART 发送失败
    - 运行异常（try/except）

- 不记录逐帧检测日志，以避免性能损耗与日志噪音

- 调试信息与系统事件日志相互独立，调试输出不会影响正式运行行为


构思报告：

采用“中心-外围双 ROI 分区”将驾驶员检测与周边入侵检测解耦，并使用双状态机对两区域检测结果进行时序滤波，降低 YOLO 检测抖动导致的误报。

系统未直接读取叉车 CAN/电机运行信号（原因：不同车型协议不统一且改装接线风险高），因此采用视觉方式在中心 ROI 内检测驾驶员存在作为“叉车运行状态”的代理信号，并结合外围 ROI 的人员入侵检测实现报警触发。
